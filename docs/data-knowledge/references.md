# Data and knowledge reference shelf

This shelf is an entry point, not a ranking. Prefer primary specifications, official documentation, maintained repositories, and papers whose methods and limitations are inspectable. Check release status and licensing before using a project in production.

## Standards and public guidance

* [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework) — risk-management context.
* [NIST Privacy Framework](https://www.nist.gov/privacy-framework) — privacy-risk management.
* [W3C RDF 1.1 Concepts](https://www.w3.org/TR/rdf11-concepts/) — graph data model.
* [W3C OWL](https://www.w3.org/OWL/) — ontology standards.
* [W3C PROV](https://www.w3.org/TR/prov-overview/) — provenance model.
* [W3C Data Privacy Vocabularies](https://www.w3.org/TR/dpv/) — privacy and processing vocabulary.

## Research and evaluation

* [RAG: Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401) — foundational RAG work.
* [BEIR](https://github.com/beir-cellar/beir) — heterogeneous information-retrieval benchmark.
* [MTEB](https://github.com/embeddings-benchmark/mteb) — embedding benchmark suite.
* [HELM](https://crfm.stanford.edu/helm/latest/) — holistic language-model evaluation.

## Maintained implementation references

* [FAISS](https://github.com/facebookresearch/faiss) — vector similarity search library.
* [Sentence Transformers](https://www.sbert.net/) — embeddings and reranking.
* [pgvector](https://github.com/pgvector/pgvector) — vector search in PostgreSQL.
* [LlamaIndex](https://github.com/run-llama/llama_index) — data and context framework.
* [RAGAS](https://github.com/explodinggradients/ragas) — RAG evaluation.
* [OpenLineage](https://openlineage.io/) — lineage ecosystem.
* [SDV](https://github.com/sdv-dev/SDV) — synthetic data tooling.
* [Great Expectations](https://github.com/great-expectations/great_expectations) — data validation.
* [Apache Atlas](https://github.com/apache/atlas) — metadata and governance.

## How to assess a new link

Before adding an external reference, check the publisher or maintainer, license, documentation quality, activity, issue history, versioning, security posture, and whether the project makes claims supported by reproducible evidence. Mark experimental projects clearly and do not treat popularity as proof of correctness.
