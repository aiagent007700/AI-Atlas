# Sprint 6: trust, security, and governance

This sprint adds the layer that asks whether an AI system should be trusted with a particular decision or action.

## Added

- Threat modeling for AI applications
- Prompt injection and indirect instruction attacks
- Privacy, provenance, and data governance
- Governance, standards, and regulation
- Assurance cases and release gates
- A visual map of the trust and control stack

## Editorial stance

The tutorial distinguishes between:

- A model being capable
- A system being reliable for a defined task
- A deployment being authorized and accountable

Those are different claims and require different evidence.

## Suggested learning order

1. Read the threat-modeling chapter.
2. Study prompt injection as an authority problem.
3. Trace data from source to output.
4. Compare standards, regulation, and guidance.
5. Build an assurance case for one proposed AI capability.

## Daily-layer hooks

Future daily updates should classify security and governance developments by:

- New attack technique
- New evaluation method
- New standard or guidance
- New regulatory obligation
- New incident or postmortem
- New deployment control

## The question to carry forward

> What evidence would make you increase or reduce the authority granted to an AI system?
